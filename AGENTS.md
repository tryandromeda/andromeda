# Writing rules

- Write complete, direct sentences instead of separating phrases with a dash, such as "Blabla - ok".
- Do not use em dashes anywhere.
- Do not use colons in comments, including documentation comments.

# Comments

- Keep comments brief and use them only for a useful overview or to explain why something is done.
- Do not narrate or re-explain the code.
- Keep the implementation as the source of truth. Comments must not duplicate behavior, algorithm steps, or values that can drift from the code.
